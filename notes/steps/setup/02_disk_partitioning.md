# 02 Disk Partitioning

This document covers partitioning, formatting, and mounting the second virtual disk (`/dev/sdb`) that will hold the LFS system.

> **Before starting:** You must be logged into the **host OS** (installed on `/dev/sda`). The ISO is still attached but not needed — leave it for now.

```bash
# Image mode (default, LFS_DISK empty in config/ft_linux.conf) — used on WSL:
# creates the sparse raw image $LFS_IMAGE (30G), attaches it to a free loop
# device (losetup -fP → /dev/loopN, partitions /dev/loopNp1..p3).
sudo bash scripts/01_setup/01_disk_partition.sh

# Block mode — a real second disk (e.g. the original VirtualBox setup below):
sudo bash scripts/01_setup/01_disk_partition.sh /dev/sdb

# After every WSL / host restart (loop devices and mounts are not persistent):
sudo bash scripts/lfs_disk.sh mount     # or: umount | detach | status
```

> The script does **not** touch the host `/etc/fstab` (an fstab entry for a
> loop partition would break the host boot). Section 5 below is kept only as
> background for the manual VirtualBox procedure.
>
> At the end the image becomes the evaluation disk: `qemu-img convert -O vdi`.
> Inside the VM the disk is `/dev/sda`, so p1/p2/p3 → `/dev/sda1..3`, matching
> the fstab and grub.cfg generated by `scripts/03_system/`.

## Prerequisites

Set the `LFS` variable — you will need it in every step below:

```bash
export LFS=/mnt/lfs
```

> This only lasts for the current shell session. Re-run it if you open a new terminal.

---

## 1 Verify the second disk

Confirm that `/dev/sdb` (the empty LFS disk added in VirtualBox) is visible:

```bash
lsblk
```

Expected:
```
sda      30G   ← Host OS disk
├─sda1   ...
└─sda2   ...
sdb      30G   ← LFS disk (empty, no partitions yet)
```

> If the disk is not visible, shut down the VM and verify the second disk is attached in **VirtualBox → Settings → Storage**.

---

## 2 Partition the disk

```bash
sudo fdisk /dev/sdb
```

Inside `fdisk`, run these commands in order:

The partition **numbers** must match the fstab and grub.cfg generated by `scripts/03_system/`:
`1` = `/boot`, `2` = `/` (root), `3` = swap. Inside the VM this disk becomes
`/dev/sda`, so root ends up at `/dev/sda2` — the device GRUB boots from.

| Command sequence | Result |
|---|---|
| `n` → `p` → `1` → Enter → `+512M` | Partition 1: LFS `/boot` (512 MB) |
| `n` → `p` → `2` → Enter → `+27G` | Partition 2: LFS `/` root (size to taste) |
| `n` → `p` → `3` → Enter → Enter | Partition 3: swap (remaining space) |
| `t` → `3` → `82` | Set partition 3 type to Linux swap |
| `w` | Write and exit |

Verify:
```bash
lsblk /dev/sdb
```

Expected:
```
sdb      30G
├─sdb1  512M    ← LFS /boot
├─sdb2   27G    ← LFS / (root)
└─sdb3  2.5G    ← swap
```

---

## 3 Format the partitions

```bash
sudo mkfs.ext4 -F -L "lfs-boot" /dev/sdb1   # LFS /boot
sudo mkfs.ext4 -F -L "lfs-root" /dev/sdb2   # LFS / (root)
sudo mkswap       -L "lfs-swap" /dev/sdb3   # swap
```

---

## 4 Mount the partitions

```bash
# Mount root FIRST, then boot inside it
sudo mkdir -pv $LFS
sudo mount -v -t ext4 /dev/sdb2 $LFS

sudo mkdir -pv $LFS/boot
sudo mount -v -t ext4 /dev/sdb1 $LFS/boot

# Enable swap
sudo swapon -v /dev/sdb3
```

Verify:
```bash
mount | grep lfs
swapon --show
df -h $LFS $LFS/boot
```

---

## 5 Make mounts persistent across reboots

> **Not done by the scripts** (and never for image mode): use
> `sudo bash scripts/lfs_disk.sh mount` after a reboot instead. Manual
> alternative for a dedicated build VM with a real second disk only:

```bash
sudo bash -c 'cat >> /etc/fstab << "EOF"

# LFS partitions (second virtual disk)
LABEL=lfs-root  /mnt/lfs       ext4  defaults  0  2
LABEL=lfs-boot  /mnt/lfs/boot  ext4  defaults  0  2
LABEL=lfs-swap  none           swap  sw        0  0
EOF'
```

> After a reboot the partitions will auto-mount, but you will still need to re-run `export LFS=/mnt/lfs` in your shell. This is handled in the next step.

---

## 6 Remove the ISO from VirtualBox

Now that the LFS partitions are set up and the host OS mounts are persistent, you can safely remove the ISO:

1. **Shut down the VM** (or do this while it's running — VirtualBox allows it).
2. Go to **Settings → Storage**.
3. Click on the optical drive entry under the controller.
4. Click the disk icon on the right → **Remove Disk from Virtual Drive**.
5. Start the VM. It will now boot directly from `/dev/sda` (the host OS).

> If the VM fails to boot after removing the ISO, go to **Settings → System → Boot Order** and make sure **Hard Disk** is above **Optical**.
